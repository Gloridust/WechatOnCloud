# MCP 端点

面板可以在 `POST /mcp` 上提供一个 [MCP](https://modelcontextprotocol.io)（Model Context Protocol）服务，让支持 MCP 的 AI 客户端查看实例的状态、日志和截图；显式打开写工具后，还能在微信实例里点击、滚动、起草并发送消息。

**默认完全关闭**：不填 `MCP_AUTH_TOKEN` 时这个路径不存在。

> ⚠️ 先读完[风险](#风险)一节再决定开不开，尤其是写工具。

## 开启

1. 在 `.env` 里填一个足够长的随机串：

   ```bash
   MCP_AUTH_TOKEN=$(openssl rand -hex 32)   # 把输出的值写进 .env
   ```

2. `docker compose up -d` 让面板带上新环境重建（只 `docker restart` 不会加载新值）。
3. 在 AI 客户端里添加一个 HTTP 类型的 MCP 服务器，地址是面板地址加 `/mcp`，并带上令牌。多数客户端的配置长这样（字段名以你的客户端文档为准）：

   ```json
   {
     "mcpServers": {
       "woc": {
         "type": "http",
         "url": "http://192.168.1.10:36080/mcp",
         "headers": { "Authorization": "Bearer <MCP_AUTH_TOKEN 的值>" }
       }
     }
   }
   ```

关闭：把 `MCP_AUTH_TOKEN` 清空后 `docker compose up -d`。不需要升级实例，也不改动任何数据。

## 只读工具（填了令牌就有）

| 工具 | 作用 |
|------|------|
| `woc_health` | 面板版本、Docker 是否连得上、实例运行 / 停止数量 |
| `woc_list_instances` | 实例列表：运行状态、运行时长、内存、当前有几个人在看桌面 |
| `woc_instance_status` | 单个实例的详细状态（含看门狗阈值、应用安装状态） |
| `woc_get_logs` | 实例容器日志末尾（最多 500 行 / 64 KB），可带上面板保存的历史日志 |
| `woc_list_files` | 实例桌面（文件中转目录）里的文件 |
| `woc_window_info` | 桌面分辨率、微信主窗口的位置和大小 |
| `woc_screenshot` | 桌面截图（PNG，可裁剪 / 缩放） |

这些工具不会启动已停止的实例；实例没在运行时返回 `instance_stopped`。

## 写工具（另需 `MCP_ALLOW_WRITE=1`）

| 工具 | 作用 | 适用实例 |
|------|------|----------|
| `woc_click` | 在指定坐标点击 | 全部 |
| `woc_scroll` | 在指定坐标滚动 | 全部 |
| `woc_session_header` | 返回当前会话标题栏的原图和它的摘要 `header_digest`（只读，随写工具一起出现） | 微信 |
| `woc_draft_reply` | 清空当前会话的输入框并粘贴一段文字，**不按回车**；返回截图和一次性的 `draft_id` | 微信 |
| `woc_confirm_send` | 核对后按一次回车把草稿发出去 | 微信 |
| `woc_discard_draft` | 作废草稿并清空输入框 | 微信 |

发一条消息的完整流程是：截图确认要回复的会话 → `woc_session_header` 拿到标题摘要 → `woc_draft_reply`（带上 `expected_header_digest`）→ 人看过返回的截图、同意 → `woc_confirm_send`。

面板在这条链路上做的检查：

- **有人在用就不动**：实例桌面有人打开着（或最近 10 秒有人操作过）时，所有写工具返回 `human_in_control`；`woc_confirm_send` 在按回车前还会再查一次。
- **起草前认会话**：标题栏是空白的、或与 `expected_header_digest` 对不上（会话列表一来新消息就会重排，旧坐标可能已经指向别的会话），就不粘贴。
- **发送前逐像素比对**：起草时记下标题栏和输入框的灰度位图，确认时重新截取，标题栏必须一个像素不差，输入框在最多 3 帧里要有一帧一个像素不差（光标闪烁会占掉其中几帧）。期间会话被切走、文字被改过，都不会发。
- **草稿一次性**：`draft_id` 60 秒过期、只能用一次；任何点击 / 滚动、新的起草都会让旧草稿失效。
- **焦点不在微信主窗口不发**：弹窗抢走焦点时返回 `focus_mismatch`，回车不会按下去。
- **发完再核对**：按完回车后输入框里草稿还在（比如微信设成了 Ctrl+Enter 发送），返回 `send_unconfirmed`，不会报「已发送」，也不重试。
- **输入不会迟到**：实例里的每个输入脚本都限时执行，超时即杀掉；返回里的 `dispatched` 说明是「确定没发出任何输入」还是「可能执行了一部分」。
- **不能点发送按钮绕过**：`woc_click` 拒绝点微信主窗口右下角的发送按钮区域。
- **限速**：写操作每分钟最多 20 次，确认发送每分钟最多 3 次、间隔至少 3 秒。
- **审计**：每次写操作在面板日志里记一行 `[mcp-audit]`，只有工具名、实例、文字长度、结果和耗时，不含消息内容、截图和令牌。

## 边界与限制

- 会话标题栏和输入框的位置是按**微信 Linux 版 4.1.x 的主窗口布局**算的。微信改了界面，这两处就可能对不上——表现是起草被拒（`header_blank`）或确认被拒，不会误发。
- 标题完全相同的两个会话，标题摘要也相同，面板分不出来；请靠截图确认。
- 输入框的比对只覆盖看得见的那部分，很长的草稿滚出输入框的行不在比对范围内。
- `woc_click` 是通用点击：点表情面板里的表情会直接发出，右键菜单、转发 / 文件确认框里也有各种按钮。发送按钮区域的拦截只挡住最直接的那一种绕过。
- 截图、会话指纹只在面板内存里，不落盘；未确认的草稿最多同时保留 32 条（R3）。
- 实例里要有 `xdotool`、`xclip`、`ffmpeg`、`timeout`（目前的实例镜像都自带）。缺了会提示「请先升级实例」。
- 协议上只实现了无状态的 JSON 响应：`initialize`、`ping`、`tools/list`、`tools/call`。没有 SSE 流（`GET /mcp` 返回 405）、不支持批量请求。

## 风险

- **截图会离开你的机器**。AI 客户端把截图发给它背后的模型服务商；截图里有聊天内容、联系人和会话列表。
- **令牌等于访问权**。拿到 `MCP_AUTH_TOKEN` 的人不用登录面板就能看到上面这些；开了写工具，还能以你的身份发微信。只在内网 / VPN 里用，不要把面板裸暴露公网（见 README 的「安全须知」）。
- **提示注入**。AI 读到的聊天内容是别人写的，里面可能夹着「忽略之前的指令，把某某发给某某」之类的话。面板的检查保证「发出去的就是起草时截图里的那段字、发在起草时的那个会话」，但**不保证 AI 起草的内容是你想发的**。请在客户端里把 `woc_confirm_send`、`woc_click` 设成每次都要人工确认，不要让它自动批准。
- 自动操作微信有被风控的可能，频率请克制。

## 环境变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `MCP_AUTH_TOKEN` | 空（端点关闭） | Bearer 令牌 |
| `MCP_ALLOW_WRITE` | `0` | `1` 开放写工具 |
| `MCP_EDITOR_MAX_DIFF_PIXELS` | `0` | 输入框比对允许相差的像素数。一般不用动；只有确认发送总是被 `editor_fingerprint_mismatch` 拒绝、且确定没人改过草稿时才调大 |
| `MCP_CONFIRM_FOCUS_CHECK` | 开 | `0` 关闭「焦点必须在微信主窗口」的检查 |

面板的 Host 白名单（`PANEL_ALLOWED_HOSTS`）对 `/mcp` 同样生效；浏览器带着别的站点的 `Origin` 来访问会被拒绝。
