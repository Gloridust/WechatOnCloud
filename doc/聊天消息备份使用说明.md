# 聊天消息备份使用说明

## 一句话

在管理后台 → 数据卷弹窗里新增了「聊天消息备份」区：可对任意实例做**全量**或**增量**聊天数据备份，产物保存在 NAS 面板数据目录（`./data-panel/chat-backups/<实例ID>/`），可下载、恢复、删除。

## 怎么用

1. 管理后台 → 实例卡片 → **数据卷**（管理员专属）→ 弹窗下方「聊天消息备份（全量 / 增量）」。
2. **全量备份**：首次必做，生成完整聊天数据基线包。
3. **增量备份**：之后点它，只打包相对上一次变化的文件（省时间/空间）。
4. 每条备份可 **下载**（`.tar.gz`）、**恢复**（覆盖当前数据，会先停实例再启动）、**删除**。
5. 点「刷新列表」查看历史。

## 备份了什么

| 应用类型 | 备份路径（容器内 `/config` 下） | 内容 |
|---|---|---|
| 微信 | `xwechat_files`、` .xwechat`、`.woc-machine-id`、`Desktop` | 聊天库/资源、运行时索引、解密机器 ID、收到的文件 |
| QQ | `.config/QQ` | NTQQ 消息库（`nt_db/nt_msg.db` 等） |
| Telegram | `.config/telegram` | 数据目录 |

**不含**：微信/QQ 程序本体（可从镜像重装）、`core` 崩溃 dump、浏览器缓存。整卷备份（原有功能）仍然保留，用于跨实例迁移/完整离线归档。

## 重要限制（务必理解）

1. **加密库不能直接阅读**。微信 `message_0.db` 是 SQLCipher 加密的，`备份文件本身无法用 sqlite 工具打开`。
   - 恢复方式：用本面板的「恢复」按钮 → 恢复到原 WOC 环境，靠 `.woc-machine-id` 解密延续聊天记录。
   - **跨设备/换机器 ID 直接拷库不保证能解密**。
2. **备份期间应用会短暂冻结**（约几秒：对微信进程发 SIGSTOP 暂停写入，保证聊天库快照一致，随后自动恢复）。桌面不重启、登录态不变，只是这几秒内应用点不动。备份要求实例处于「运行中」。
3. **增量粒度是「文件」**。加密库无法做记录级差异；聊天库文件本身变动频繁，增量的省空间主要来自图片/语音/视频等大资源文件。
4. **删除基线的风险**：增量恢复需要从其 full 基线依次回放。删除某条 full 会让依赖它的增量无法单独恢复（删除前有确认提示）。自动保留策略只会清理旧轮次，永不删当前基线。
5. **恢复会覆盖当前聊天数据**，操作前确认；恢复期间实例停止后自动启动。

## 自动增量（可选）

默认关闭。在面板环境变量里开启：

```
WOC_CHAT_BACKUP_AUTO=1
WOC_CHAT_BACKUP_CRON_MIN=360      # 每 360 分钟（6 小时）一次；无基线时自动先做全量
WOC_CHAT_BACKUP_KEEP=0            # 额外保留的旧轮次条目数，0=只留当前轮次
```

compose 里在 `panel.environment` 增加这三行后 `docker compose up -d --force-recreate panel` 生效。手动备份不需要这些变量。

## 存储与空间

- 产物落在面板容器 `/data/chat-backups/<实例ID>/`（宿主 `./data-panel/chat-backups/<实例ID>/`）。
- 微信全量一次约 **4~5 GB**（`xwechat_files` 4.1G + `.xwechat` 723M）。请确保 `data-panel` 所在磁盘有空间。
- 自动备份时建议设置 `WOC_CHAT_BACKUP_KEEP` 避免无限增长。

## API（管理员令牌）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/instances/:id/chat-backup` | `{mode:'full'\|'inc'}` 触发，返回任务号 |
| GET | `/api/admin/instances/:id/chat-backup/jobs/:job` | 轮询进度 |
| GET | `/api/admin/instances/:id/chat-backup` | 列出备份链 |
| GET | `/api/admin/instances/:id/chat-backup/:entryId/download` | 下载备份包 |
| DELETE | `/api/admin/instances/:id/chat-backup/:entryId` | 删除备份 |
| POST | `/api/admin/instances/:id/chat-backup/:entryId/restore` | 恢复到该 entry |
