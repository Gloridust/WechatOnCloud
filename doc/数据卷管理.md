# 数据卷管理与数据迁移

> 返回 [← README](../README.md)

**管理员专用。** 每个实例的「数据卷」= 容器内 `/config` 持久卷，含微信全部数据（登录态、加密聊天库、配置等）。
入口：**管理页 → 实例卡片右下角的「⋯」→ 数据卷**。子账号不可见（数据卷等同完整微信会话凭据）。

提供两块能力：**整卷备份 / 恢复** 与 **文件浏览器**（浏览 / 上传 / 上传并解压 / 下载 / 改名 / 移动 / 删除）。

---

## 整卷备份 / 恢复（最可靠）

- **下载整卷备份**：把 `/config` 流式打包成 `.tar.gz` 下载（大文件不进内存，边打包边下）。用于离线备份、换宿主、跨实例迁移。
- **恢复备份**：上传 `.tar.gz`，把 `/config` **还原**成备份里的样子：备份里没有的文件也会删掉，不会新旧混在一起。包会先完整收下、整体校验（格式、是否完整、是否本系统导出的备份，即所有条目都在 `config/` 下），不合格直接拒绝、什么都不写；校验通过后实例若在运行，会**自动停止 → 写入 → 自动启动**，不必再手动重启。写入前现有数据先挪进卷里的 `.woc-restore-old-<时间>` 目录（同一个卷里改名，很快），写完才删；写入出错就清掉写了一半的数据、把它挪回来，实例回到恢复前的样子。所以恢复时数据盘要有不少于备份大小的空闲，不够会在动手前直接提示。早期的备份里没有设备标识 `.woc-machine-id` 时，沿用实例原来的。万一恢复途中面板被重启，原来的数据会留在那个目录里，可以在文件浏览器里移回根目录。
- **为什么能保留聊天记录**：唯一设备标识存在卷内的 `.woc-machine-id`，会随备份一起迁移 → 目标实例解密环境一致，聊天记录可还原。这也是 woc 实例之间迁移的推荐方式。详见 [设备伪装](设备伪装.md)。

> 备份大小 ≈ 卷大小（微信数据常为数百 MB ~ 数 GB），请按网络情况耐心等待。上传时显示进度，传完后界面依次显示「校验压缩包 / 检查空间 / 停止实例 / 挪开现有数据 / 写入数据 / 清理旧数据 / 启动实例」。
>
> 上传的包会先暂存在面板数据目录（`./data-panel/.upload-tmp`，处理完即删、面板重启时清空），所以面板数据目录所在的盘至少要留出与包同样大的空间；不够时直接提示空间不足，不会写一半。单个包上限 100 GB。

## 把 PC 微信数据迁移上来

1. 在 PC 上把微信数据文件夹打包成 `.tar.gz`；
2. 数据卷 → 进入目标目录 → 「**上传并解压**」（也支持 `.tar`；zip 暂不支持）；
3. 在卡片的「⋯」菜单里点「重启」。

「上传并解压」同样是先收完、校验通过再写入：包不完整、含 `..` 越界路径或设备文件时整包拒绝，不会解出一半。解出来的文件一律改为容器内 `abc` 属主（压缩包里记录的属主不管是 root 还是 Mac 上的 501 都会被改掉），应用能正常读写；符号链接只改它自己，不会顺着改到链接指向的文件。

> ⚠️ **能否解密取决于微信版本与设备绑定**：微信本地库通常按设备/账号加密，跨设备直接复制数据库**不保证**能在新实例打开，请自行测试。最可靠的是「本系统导出的整卷备份」在 woc 实例间恢复。

## 安全与注意

- **仅管理员**可用；子账号永不可见（数据卷 = 完整微信会话凭据）。管理员本就持有 `docker.sock`（宿主 root），不新增风险。
- 所有路径严格限制在 `/config` 内，禁止 `..` 穿越。
- **全程在「运行中」的实例上操作**（底层用 `docker exec` 浏览/改名/删除、用 `docker cp` 传输）。改动微信正在使用的数据后，需**重启实例**方可生效；大改动前建议先「下载整卷备份」留底。
- 实例**未运行**时：只能做整卷备份 / 恢复；文件浏览需实例运行中。
- 上传的文件落地为容器内 `abc` 属主（按 `WOC_PUID` / `WOC_PGID`，微信进程可读写）。单个文件边收边写（面板内存不随文件大小增长），先写到 `/config/.woc-upload` 下的临时文件，收完整才改名到目标位置，上传中断不会留下半截文件；单个文件上限 20 GB（桌面文件中转 4 GB）。
- 通过反代访问时，反代也要放行大请求体，见 [部署与运维 · 反代](部署与运维.md#公网访问--反代部署nginx-示例)。
